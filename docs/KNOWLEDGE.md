# Knowledge stores

janus keeps facts in nine places. Each is split by how long the fact lasts and who needs it, so nothing is
duplicated and nothing that should be gone is still being read. This page is the map: for each store, who
writes it, who reads it, when it is injected, and how it is kept small.

| Store | Written by | Read by | Injected | Kept small |
|---|---|---|---|---|
| **Owner rules** (beads memories) | the orchestrator, when the owner gives a standing instruction (`bd remember "<rule>" --key <subject>`) | the orchestrator; any agent the project tells to read beads | at session start with the rules; agents where their instructions say to run `bd prime` | one entry per subject key — a rule that changes an older one **replaces** it (same key), it never sits beside it |
| **Session memory** (`MEMORY.md`) | the orchestrator only (`janus remember` / `janus forget`) | the orchestrator and every agent | into **every brief**, and at session start | `[memory] cap_lines` (about 30), one dated line per entry; replaced or forgotten entries go to `memory-history.md`; `review_days` prompts a review |
| **Decision records** (`.janus/decisions/NNNN-title.md`) | the orchestrator (an owner ruling or an orchestration decision) | the orchestrator; agents get the index pointer | the index at session start | one short file per decision; one index line each; a record is never edited — a change is a new record that supersedes it |
| **Handoff** (`HANDOFF.md`) | the orchestrator — Live state regenerated by `janus check`, the notes by hand | the orchestrator, at session start and after a reset | at session start, with the rules and `janus check` | notes under 150 lines; old notes move to history; the Live state is generated, never hand-written |
| **History** (`history.md`) | the orchestrator (what leaves the handoff) | a person or the orchestrator, on demand | never | it is the archive: it grows, and is never loaded whole |
| **Board** (`board.sh`) | agents (state changes); the orchestrator (directions and answers) | the orchestrator — a new question or block wakes it — and the peers | the peers file and the reports index are pointed to in every brief; `digest` is for the owner | state changes only, steps go in the report; a question closes when answered; cards of closed units are archived |
| **Reports and the reports index** (`out/<unit>/REPORT.md`, `out/INDEX.md`) | agents (the report); the orchestrator (the index) | the orchestrator, at close and collect; agents via the index pointer | the index pointer, not the reports | one `VERDICT` line per report; the index is one line per unit, newest first; old reports are not loaded |
| **Unit records** (beads issues) | the orchestrator (launch, close, comments) | the orchestrator (ready work, the queue); the unit's own agent | statuses surface in `janus check`; the records themselves are not injected | one issue per unit, its notes hold the record; finished units are closed |
| **Transcripts** (`out/<unit>/transcript.md`) | the agent runtime; saved by the orchestrator at collect | the orchestrator and agents, on demand | never | read by `--grep` or `--tail`, never whole |

## Why this shape

The split follows two questions: how long does the fact last, and who needs it.

- A **rule** lasts until replaced and binds everyone, so it lives in the shared unit store with a subject
  key, and a new one replaces the old.
- A **decision** is a dated snapshot of one choice, so it is one immutable file with an index; a reversal
  is a new record, not an edit.
- **Session memory** is what guides agents *now*, so it is curated, small and injected into every brief.
- The **handoff** is live state plus the orchestrator's notes, so its state part is regenerated and its
  notes are kept under a page.
- **History** is the past, so it is never injected.
- The **board** is work in flight, so it holds only state changes and closes as work closes.
- **Reports** are results and the **transcripts** are raw material, so they are kept for the record and
  read only on demand.
- **Unit records** are the backlog and the queue, so they live where the scheduler reads them.

## The rule

**One place per fact; link, do not copy.** When a fact belongs to a store, write it there once and point
to it from everywhere else — the brief header points to the reports index and the peers file, a decision
record links to a product decision instead of restating it, and a rule is replaced in place rather than
copied beside itself. A fact in two places drifts; a link does not.
